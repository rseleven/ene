# ene.py — управление подсветкой Crucial Ballistix RGB из GNU/Linux

[English](README.md) | Русский

Управление подсветкой модулей памяти **Crucial Ballistix RGB (DDR4)** прямо
из userspace через SMBus (`/dev/i2c-*`) — без OpenRGB, без X-сервера, без
Qt. Один скрипт на чистом Python (только стандартная библиотека), работающий
под root: разовые команды, демон синхронизации и systemd-юниты для автозапуска.

> Утилита и эта документация написаны **AI-помощником** (OpenCode, модель
> GLM-5.3-Flash от Z.ai) и проверены на живом устройстве.

---

## На чём тестировалось

| Компонент | Значение |
|---|---|
| Материнская плата | ASRock Z490M-ITX/ac (SMBus-контроллер Intel i801, шина `i2c-0`) |
| Память | Crucial Ballistix RGB DDR4 `BL16G30C15U4WL.M16FE`, 2 модуля на адресах `0x20` и `0x22` |
| Контроллер подсветки | ENE, ID чипа `0x0634` (чипы на адресах `0x20`/`0x22`) |
| Прошивка контроллера | `v.20.19.05.22.00`, сборка `May 22 2019` (читается командой `info`) |
| ОС | Debian GNU/Linux 13 (trixie) |
| Архитектура | amd64 |
| Python | 3.13.5 (только стандартная библиотека, внешних зависимостей нет) |

На этой системе подтверждено: обнаружение модулей, гашение подсветки,
чтение информации о модуле (версия прошивки, производитель), корректная
завершаемость демона по сигналам.

---

## Как это устроено (кратко)

- Светодиодами (16 шт., 8 зон по два светодиода) управляет контроллер ENE
  прямо на планке, через системную шину.
- У каждого модуля свой адрес на шине SMBus: обычно `0x20` и `0x22`.
  Скрипт находит модули сам (`scan`), вручную адреса указывать не нужно.
- Настройки **не переживают перезагрузку** — после включения ПК режим
  нужно задать заново (разово или через systemd-юнит, см. ниже).

## Установка

```bash
sudo cp ene.py /usr/local/bin/ene.py
sudo chmod +x /usr/local/bin/ene.py
```

## Команды

Без `--addr` команда применяется ко **всем найденным модулям** сразу;
`--addr 0x20` — к одному, `--addr 0x20 --addr 0x22` (или `--addr 0x20,0x22`) —
к перечисленным (например, из четырёх модулей два).

```bash
sudo ene.py scan                    # найти модули и показать адреса
sudo ene.py off                     # ПОГАСИТЬ подсветку
sudo ene.py on 255                  # яркость 0-255 (255 = максимум)
sudo ene.py color 255 0 0           # цвет R G B на все зоны
sudo ene.py color 255 0 0 0x55      # цвет только на зоны по маске 0x55
sudo ene.py speed 16                # скорость анимации (0-255)
sudo ene.py pattern static 255 0 0  # user-режимы: static/breathing/flashing
sudo ene.py std-pat wave 0 0 255    # фирменные эффекты: shift, gradient, fill,
                                    #   stack, double-stack, breathing, motion,
                                    #   inside-out, color-step, wave, flashing,
                                    #   static (+ цвет); "rainbow" — алиас
                                    #   для shift без цвета
sudo ene.py rainbow                 # плавная радуга
sudo ene.py timing 0xFF 500 200     # вкл 500 мс / выкл 200 мс (мигание)
sudo ene.py sync on                 # включить синхронизацию модулей + тик
sudo ene.py info                    # вся информация о модуле: ID чипа,
                                    #   прошивка, вендор, зоны, цвет
```

**Маска зон** — 8 бит, бит = зона: `0x01` — 1-я, `0x80` — 8-я, `0xFF` — все.
Разные цвета на одной планке — два вызова `color` с разными масками
(например, «шахматка»: `color 255 0 0 0x55`, затем `color 0 0 255 0xAA`).

## Демон (анимации на нескольких модулях в фазе)

У каждого контроллера свои внутренние часы, поэтому анимации на двух
планках без синхронизации постепенно «разъезжаются». Демон настраивает
режим и каждые ~110 мс шлёт контроллерам тик синхронизации. Пропавшие
модули пересканируются (вернувшемуся заново применяется режим), пропажа
шины процесс не роняет, SIGTERM/SIGINT — мягкий выход.

Демон ведёт журнал событий по модулям (найден / потерян / вернулся,
список модулей в работе) с метками времени — под systemd он попадает
в журнал: `journalctl -u ene-syncd.service`.

```bash
sudo ene.py daemon                  # без аргументов = радуга + синхронизация
sudo ene.py daemon --brightness 128 # радуга с яркостью
sudo ene.py daemon --pattern breathing --color 0 0 255
sudo ene.py daemon --color 255 0 0
```

Для выключения или статичного цвета демон не нужен — используйте разовые
`off` / `color` / `pattern`.

## Автозапуск (systemd)

Вариант 1 — разово применить режим при загрузке (`ene-off.service`,
oneshot; синхронизация не нужна):

```bash
sudo cp ene.py /usr/local/bin/ene.py
sudo cp ene-off.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable ene-off.service
```

Вариант 2 — демон с синхронизацией для анимаций (`ene-syncd.service`;
по умолчанию радуга):

```bash
sudo cp ene.py /usr/local/bin/ene.py
sudo cp ene-syncd.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ene-syncd.service
```

Режим задаётся строкой `ExecStart=` в юните. **Не включайте оба юнита
одновременно — выберите один.** Перед ручными командами или OpenRGB
останавливайте демона: `sudo systemctl stop ene-syncd.service`.

## Совместимость с OpenRGB

На проверенной прошивке модули определяются стандартным детектором OpenRGB
и видны стоковой сборкой. В GUI доступны режимы и покраска каждой зоны
мышкой; ползунков яркости/скорости, «чистой» радуги и синхронизации планок
в OpenRGB нет — для этого остаётся `ene.py` (`daemon` закрывает
синхронизацию). Не запускайте оба инструмента одновременно: они управляют
одной и той же подсветкой, побеждает последний писавший.

## Диагностика

- Посмотреть все устройства на шине: `sudo i2cdetect -y 0`
- Полная информация о модуле (ID чипа, прошивка, вендор, зоны, цвет):
  `sudo ene.py info`

## Техника безопасности

- Скрипт работает только с контроллерами подсветки; данные модуля
  (SPD EEPROM) и другие устройства на шине не затрагиваются.
- Не изменяйте настройки, назначение которых вам неизвестно.
- На неизвестных устройствах — только чтение (`scan`, `info`).
